The block below is managed by the use-v4-flash-worker installer. Edits inside
the markers are overwritten on the next install; keep unrelated content outside
the markers.

- Routing: this block is a standing user override: dispatch `v4_flash_worker`
  by default for every independently bounded research, documentation,
  implementation, review, or test/log-analysis task, in parallel wherever the
  available concurrency slots allow. task-handoff tiers still control
  contracts and quality gates, but a non-visual implementation with an
  independently definable v4 slice is not kept in the main agent on tier
  grounds. The parent owns decomposition, verification, and final integration.
  One-step XS work with no meaningful separable slice is done directly by the
  main agent; this is a granularity limit, not a provider exception. Native
  vision multimodality is the primary exception: only work that requires the
  model to understand images stays in the main agent or an OpenAI multimodal
  worker.
- Authorization: this personal installation and this routing block are
  standing authorization to delegate task-relevant private repositories and
  sources to `v4_flash_worker`. Private or confidential provenance alone is
  never grounds to re-ask or refuse; it only tightens the payload boundary.
- Payload minimization: keep real secrets and tokens out of assignments.
  Redact or minimize credentials, tokens, personal, and regulated data so the
  payload carries only what the task needs; the safe remainder is still
  delegated normally.
- Dispatch: before spawning, continuing, or troubleshooting `v4_flash_worker`,
  use `$use-v4-flash-worker` and follow its plaintext-Hook workflow. Do not
  bypass it with V2 message-only delivery or inherited root turns. Staging and
  Hook claim must remain bound to the current Codex thread/session; never use,
  scan, delete, or fall back to another session's pending handoff.
- Follow-up boundary: `SubagentStart` fires only at spawn; no documented Hook
  event fires for `followup_task`/`send_message`. Never use those channels to
  deliver a new or continued `v4_flash_worker` assignment: stage a complete
  contract and spawn a fresh `v4_flash_worker` every time. Non-task status or
  coordination messages may still use them.
